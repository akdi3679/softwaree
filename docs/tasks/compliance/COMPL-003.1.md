```markdown
# SOC 2 Type II — Controls Matrix

This document maps the AICPA Trust Service Criteria to our specific
implementation. Each control lists:
- Control ID
- Description
- Implementation (file/line)
- Test/evidence
- Frequency
- Owner

## CC1 — Control Environment

### CC1.1 — Commitment to integrity
- **Description**: All employees sign a code of conduct.
- **Implementation**: HR records, not part of codebase.
- **Test**: Manual review during audit.
- **Frequency**: Annual.

### CC1.4 — Background checks
- **Description**: All employees with production access have background checks.
- **Implementation**: HR records.
- **Test**: Manual review.

## CC2 — Communication and Information

### CC2.1 — Information quality
- **Description**: All events are recorded immutably.
- **Implementation**: `apps/admin/src-tauri/src/event_store.rs:write_event`
- **Test**: AUDIT-001 verifies hash chain.
- **Frequency**: Continuous (every write).

## CC3 — Risk Assessment

### CC3.1 — Risk identification
- **Description**: Risk register maintained.
- **Implementation**: `docs/architecture/THREAT-MODEL.md` (T1-T8 threats).
- **Test**: Quarterly review.
- **Frequency**: Quarterly.

## CC5 — Control Activities

### CC5.2 — System access controls
- **Description**: Only the Admin device of a project can write.
- **Implementation**: `apps/admin/src-tauri/src/sync/auth.rs:verify_device_signature`
- **Test**: SYNC-002 verifies all incoming commands have valid device sig.
- **Frequency**: Every command.

## CC6 — Logical and Physical Access

### CC6.1 — Logical access controls
- **Description**: All auth tokens are device-bound Ed25519.
- **Implementation**: `apps/admin/src-tauri/src/auth/crypto.rs`
- **Test**: ADMIN-005 verifies sigs.
- **Frequency**: Every request.

### CC6.6 — Encryption at rest
- **Description**: All backups encrypted with AES-256-GCM.
- **Implementation**: `apps/admin/src-tauri/src/backup/crypto.rs`
- **Test**: BACKUP-001 encryption tests.
- **Frequency**: Every backup.

## CC7 — System Operations

### CC7.1 — Vulnerability management
- **Description**: `cargo audit`, `pnpm audit`, `gitleaks` run in CI.
- **Implementation**: `.github/workflows/ci.yml`
- **Test**: CI job must pass.
- **Frequency**: Every PR.

## CC8 — Change Management

### CC8.1 — Change approvals
- **Description**: All changes require PR review.
- **Implementation**: GitHub branch protection.
- **Test**: Manual review.
- **Frequency**: Every PR.

## CC9 — Risk Mitigation

### CC9.2 — Vendor management
- **Description**: All vendors listed; security review annually.
- **Implementation**: `docs/compliance/VENDORS.md`
- **Test**: Annual review.

## Audit artifacts

These files MUST be produced for SOC 2 audit:
1. `audit-events.csv` (last 12 months) — generated by AUDIT-002
2. `access-log.jsonl` — generated by AUDIT-002
3. `chain-verify-report.json` — generated by AUDIT-001
4. `encryption-test-results.json` — generated by BACKUP-001
5. `ci-runs.csv` — exported from GitHub Actions
```
