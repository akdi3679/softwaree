# Vendor Security Review

Every external service or library we depend on must be reviewed.

## Infrastructure

### Cloud (Hetzner / OVH / DigitalOcean)
- **Purpose**: Run our Postgres + Hono + MinIO
- **Data**: Customer business data is NEVER on Cloud. Only auth, billing, backup blobs.
- **Encryption at rest**: Server-side disk encryption (provider default).
- **Encryption in transit**: TLS 1.3 only.
- **Access**: SSH key-based; ops tailnet only.
- **Review date**: 2026-01
- **Risk**: Low. Provider is ISO 27001 certified.

### our discovery service (in our Cloud)
- **Purpose**: Mesh VPN between Customer devices
- **Data**: Routing only; cannot decrypt user data.
- **Review date**: 2026-01
- **Risk**: Very low. Single binary, well-audited.

### Stripe
- **Purpose**: Billing
- **Data**: Customer name, email, payment method, invoices.
- **Compliance**: PCI DSS Level 1 (Stripe handles PAN).
- **Encryption in transit**: TLS 1.3.
- **Encryption at rest**: Stripe-managed.
- **Review date**: 2026-01
- **Risk**: Low. PCI compliant; we never see PAN.

### Resend / Postmark
- **Purpose**: Transactional email (signup verify, backup alerts)
- **Data**: Email address, content.
- **Encryption in transit**: TLS 1.3.
- **Review date**: 2026-01
- **Risk**: Low. Reputable email provider.

## Open source dependencies — review process

For any new dependency:
1. License must be MIT / Apache-2.0 / BSD-2 / ISC. GPL is forbidden.
2. Must have at least 1 release.
3. Must have 100+ GitHub stars OR be from a known org.
4. Must pass `cargo audit` / `pnpm audit` with 0 high vulns.
5. Document in `docs/compliance/DEPENDENCIES.md` (auto-generated by `pnpm dlx license-checker`).
